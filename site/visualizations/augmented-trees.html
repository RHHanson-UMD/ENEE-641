CHAPTER 14 / AUGMENTING DATA STRUCTURES

Small extra fields. Powerful queries.

Subtree sizes enable order statistics, while the maximum upper endpoint in an interval subtree lets a search skip branches safely. These are static balanced search trees illustrating the lecture's augmentation invariants—not full dynamic red-black tree insertion/deletion implementations.

Order statistics — i-th smallest element

5

At each node x, r = size(left[x]) + 1 is x's rank within its subtree. Select left if i < r, return x if i = r, or select right with rank i − r. Finding a key's global rank adds left-subtree sizes when moving right.

Interval tree — search for any overlap

The intervals are closed, so touching at an endpoint counts as an overlap. Each node stores max, the greatest upper endpoint anywhere in its subtree.

If the current interval does not overlap the query, search left when max[left] ≥ query.low; otherwise search right. The stored maximum lets us rule out a whole left subtree when every interval there ends before the query begins.

Augmentation versus rebalancing

For size augmentation, size[x] = size[left[x]] + size[right[x]] + 1. For interval augmentation, max[x] = max(high[x],max[left[x]],max[right[x]]). A balanced tree has O(log n) height, so both queries take O(log n) time. A production red-black tree must maintain these fields during rotations, inserts, and deletes; this demonstration intentionally isolates query logic on fixed balanced trees.

Operations and repair events

    Invariants and correctness

    Red-black tree: Keys obey strict BST order; NIL leaves are black; root is black; a red node never has a red child; every path from a node to its descendant NIL leaves contains the same number of black nodes. Deletion may require sibling-color and near/far-nephew cases, including mirrored rotations.

    2–3 tree: Every node holds one or two keys (except a transient deficient node during repair). An internal one-key node has two children, a two-key node three; all leaves have equal depth. Delete from a leaf, or replace an internal key with its predecessor. If a child underflows, borrow from a two-key sibling when possible; otherwise merge with a sibling through the parent separator. An empty root contracts.

    The display shows completed valid tree states; repair-event text names the temporary fix-up steps without presenting unstable intermediate structures as final trees. Try deleting a leaf, root, absent key, and all keys; both algorithms validate completed structures automatically.

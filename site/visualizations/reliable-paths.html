Reliable paths: a Dijkstra transformation

This original practice module illustrates a method discussed in the November 24 review: turn a product objective into an additive one, or adapt Dijkstra to finalize the largest product. The graph below is independently invented; it is not a homework question or solution.

Change probabilities and inspect each finalized vertex

For an edge probability r(u,v) between 0 and 1, and independent edge successes, a path's success probability is the product of its edge probabilities. A maximally reliable path maximizes that product.

Step-by-step selection

    Why the method works

    Logarithmic reduction: When r>0, define w'(u,v)=−ln(r(u,v)). Then w'≥0 and minimizing the transformed sum is equivalent to maximizing the original product:

    −ln(∏re) = Σ(−ln re). Dijkstra works with these nonnegative transformed weights. A zero-reliability edge corresponds to an infinite transformed weight; handle zero-probability routes separately if reachability matters.

    Direct Dijkstra variant: Initialize best(source)=1, all other products to 0. Repeatedly finalize the unprocessed vertex with the largest best value, and relax an edge using best(v) ← max(best(v),best(u)·r(u,v)). Because every r≤1, extending a path cannot improve its product. This provides the same greedy-finalization argument as ordinary nonnegative Dijkstra.

    Complexity: This teaching implementation selects vertices by a linear scan and visits each edge in its adjacency list, using O(V²+E) time and O(V+E) storage. A suitable priority queue can reduce selection overhead for large sparse graphs.

    Boundary and counterexample: Edges with probability 1 are allowed; product 0 is distinct from a structurally unreachable target. The path independence assumption is essential when interpreting the product as a physical probability. Using edge probabilities larger than 1 invalidates the monotonicity argument.
